1. When mail is sent

Mail is triggered when Pi emits agent_settled, meaning the agent will not automatically retry, automatically compact, or run a queued follow-up. That is the moment the task genuinely paused and is worth your attention.

pi2web only submits the message to MailDispatch. A 202 response means the mail entered MailDispatch's durable queue; actual delivery is handled by its workers.

2. CLI configuration

Three options must be provided together — endpoint, API key environment variable, and recipient — or pi2web refuses to start.

Shell
export REMOTE_PI_MAILDISPATCH_KEY='md_live_...'
pi2web \
  --maildispatch-endpoint https://mail.example.com/api/v1/messages \
  --maildispatch-api-key-env REMOTE_PI_MAILDISPATCH_KEY \
  --maildispatch-notify-to owner@example.com \
  --maildispatch-sender-id system
OptionRequiredDescription
--maildispatch-endpointYesMailDispatch message API URL; must be http or https.
--maildispatch-api-key-envYesThe name of the environment variable holding the API key, not the key itself.
--maildispatch-notify-toYesRecipient address for completion notifications.
--maildispatch-sender-idNoExplicit sender; otherwise MailDispatch picks one from the API key and service configuration.
API keys are read from the environment only.

This keeps the secret out of command lines and process listings. The key needs at least the MailDispatch mail:send scope.

3. Adjusting in the web UI

The "settings" dialog in the navigation bar enables or disables email notifications and configures:

  • Aggregation window — wait N seconds after the first completion so tasks finishing in that window share one email; 0 sends immediately.
  • Include the agent's final reply.
  • Include the session name and working path.

Settings persist in pi2web's SQLite metadata database, apply to every browser client and agent, and survive restarts.

4. Message body

With both "include final reply" and "include session info" disabled, the body only states that one or more agent tasks finished, without any project detail.

Consider content sensitivity.

A final reply may contain code snippets, paths, or internal information, and email leaves your machine. Enable those options according to how much you trust the mailbox and the mail provider.

5. Failure handling

Notification failures are written to pi2web's standard error only. They never change agent state and never block subsequent runs. Debug in this order:

  1. Check startup logs for validation errors (all three required options present, endpoint a valid URL).
  2. Verify the environment variable really exists in the shell that started pi2web.
  3. Confirm the API key has the mail:send scope and has not been revoked.
  4. Check whether MailDispatch returned 202; other status codes are printed to stderr.
  5. If mail was queued but never arrived, inspect MailDispatch delivery logs and the recipient's spam filter.
