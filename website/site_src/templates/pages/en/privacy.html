01

This website

pi2web.es2q.com is a static site with no accounts, comments, forms, or subscriptions, and no third-party analytics, advertising, or tracking scripts.

Pages load only same-origin CSS, JavaScript, and SVG icons — no external fonts or CDN resources. The web server may keep ordinary access logs (IP address, timestamp, path, user agent) for operations and security.

02

The pi2web software

pi2web is open-source software running on your own machine. It never sends sessions, code, prompts, or agent output to this project's website or to any service controlled by the author.

The software contains no telemetry, usage statistics, or crash reporting.

03

Data stored locally

~/.pi/remote-pi/remote-pi.dbServer metadata in SQLite: workspaces, agents, and the session index.
~/.pi/remote-pi/auth.jsonSHA-256 hash of the pairing code plus creation and rotation times, mode 0600, never in clear text.
~/.pi/agent/sessions/Full conversations stored as JSONL by Pi's SessionManager — managed by Pi, not pi2web.
Browser localStorageServer address, current workspace/agent, and the event cursor. The pairing code is stored only after you explicitly confirm.
Process memoryTerminal sessions and their last 512 KiB of output, released when the service exits.

Anyone with the pairing code can obtain a shell as the user running pi2web through the terminal feature. Treat it as a credential and store it only on trusted devices.

04

Network traffic

With the default configuration pi2web listens on 127.0.0.1, so traffic is limited to the local browser and the service, plus whatever Pi itself sends to the model providers you configured. Model requests are issued by Pi directly; pi2web does not proxy, cache, or log their contents.

05

Optional external services

  • Automatic session naming (enabled by default): after a turn ends, the latest user prompt and the Agent's final output are truncated and submitted to the configured OpenAI-compatible naming endpoint (default http://localhost:8313/, i.e. local) to generate a session name. If you point --session-name-base-url at a remote service, that session content leaves your machine. Disable it with --session-naming off.
  • Email notifications: only after you configure MailDispatch is notification content submitted to the endpoint you specify. You decide whether the agent reply and session information are included.
  • Voice summaries and transcription: only after you configure a speech service are summary inputs and recordings sent to the endpoint you specify.
  • Tunnels and reverse proxies: if you use devtunnel, Cloudflare Tunnel, or your own proxy, traffic passes through that provider — consult its privacy policy.

Every feature in this list except automatic session naming is disabled by default; naming is on by default and defaults to a local endpoint.
