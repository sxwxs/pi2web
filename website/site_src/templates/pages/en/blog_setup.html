1. Requirements

pi2web is a remote shell around Pi Coding Agent: it starts the real @earendil-works/pi-coding-agent SDK on your development machine and exposes it over HTTP/WebSocket to browsers and the Android client. Three things must be in place first.

  • Node.js 20.10 or newer — check with node -v.
  • A working Pi configuration — models, provider authentication, and settings are reused from ~/.pi/agent. If you have never run Pi on this machine, configure Pi itself first.
  • Native module prerequisites — installation prepares better-sqlite3 and node-pty. Most platforms use prebuilt binaries; platforms without them need Python 3 and a C/C++ toolchain (build-essential on Linux, Xcode Command Line Tools on macOS, Visual Studio Build Tools on Windows).
pi2web provides no models or quota.

It does not proxy model requests and does not host your code. All inference happens through the providers configured in your local Pi setup.

2. Installation

The npm package and the global command are both named pi2web.

Shell
npm install -g pi2web
pi2web --version

You can also run it ad hoc with npx pi2web, but a global install avoids re-downloading native modules every time.

3. First run and pairing

Run pi2web. The service listens on 127.0.0.1:11318 by default and serves the API, the WebSocket endpoint, and the web UI from the same process — no extra static file server is needed.

Shell
pi2web --host 127.0.0.1 --port 11318

The pairing code is printed once on first startup — that is the only time it appears in clear text. The server stores just its SHA-256 hash in auth.json inside the data directory with 0600 permissions, so a forgotten code cannot be recovered. Rotate instead:

Shell
pi2web --rotate-access-token

That command prints a new pairing code, invalidates the old one immediately, and exits. When you open the printed address, you must type the pairing code manually: the web UI never reads it from the URL and the server never injects it. Only after a successful connection are you asked whether to store it in localStorage — confirm this on trusted devices only.

Failed pairing is rate limited.

Ten failures from the same source address within a 60-second window trigger a lockout starting at 60 seconds and doubling up to 15 minutes, with HTTP 429 and Retry-After. WebSocket upgrades are limited too, and one successful pairing clears the counter. Limits are tracked per TCP source address, so all clients behind a tunnel or reverse proxy share a single bucket.

4. CLI options

pi2web --help lists everything. The most useful options:

OptionDefaultDescription
--host <address>127.0.0.1Listen address. Read the remote access section before switching to 0.0.0.0.
--port <number>11318Listen port.
--data-dir <path>~/.pi/remote-piMetadata directory; also settable via PI_REMOTE_DIR.
--rotate-access-token—Print a new pairing code and exit; the old code stops working immediately.
--maildispatch-endpoint <url>disabledMailDispatch message API endpoint.
--maildispatch-api-key-env <name>disabledName of the environment variable holding the MailDispatch API key.
--maildispatch-notify-to <email>disabledRecipient for agent completion notifications.
--maildispatch-sender-id <id>optionalExplicit MailDispatch sender; otherwise chosen by API key and service config.
--voice-base-url <url>disabledOpenAI-compatible speech endpoint. Without it, voice stays off entirely.
--voice-tts-model / --voice-tts-voice—Required when voice is enabled.
--voice-stt-model <id>optionalEnables the microphone button in the web UI.
--voice-summary-base-url / --voice-summary-model—LLM endpoint and model used to write the spoken summary.
--voice-request-timeout <ms>120000Timeout for speech and summary requests; on timeout the announcement degrades to text.
--version / --help—Print version or help.

The three MailDispatch options must be provided together or pi2web refuses to start. Voice options are validated only when --voice-base-url is set. Every API key is passed by environment variable name so secrets never appear in command lines or process listings.

5. Data and persistence

Server metadata lives in the SQLite database at ~/.pi/remote-pi/remote-pi.db (WAL mode):

  • workspaces — workspace ID, name, root directory, creation time.
  • agents — agent-to-workspace/session mapping, cwd, state, timestamps, archive flag.
  • sessions — a lightweight index for listing, sorting, and pagination, including name, file path, message count, and file mtime/size.
  • auth.json — the SHA-256 hash of the pairing code plus creation and rotation times, stored separately and never in clear text.

Full conversations remain in Pi's SessionManager JSONL files under ~/.pi/agent/sessions/<encoded-cwd>/. SQLite only stores a rebuildable index. Terminals exist purely in process memory and end when the service stops.

Shell
# Store metadata elsewhere, for example on an encrypted volume
pi2web --data-dir ~/pi2web-data

Changing the data directory means a different pairing code and different agent metadata. Pi's own session files are unaffected.

6. Workspaces and agents

After pairing, add a workspace: a local directory (usually a repository root) plus a name. You can then:

  • create agents whose cwd is the workspace path;
  • browse the directory tree and page through text files;
  • right-click a directory to open an interactive terminal there;
  • type @ in the composer to reference files or directories.

Agent metadata is stored in SQLite. After a restart agents are unloaded and no Pi AgentSession is created until you read messages, sessions, capabilities, or send a command; concurrent requests share a single startup. "Stop agent" releases the running session but keeps the metadata. See the web UI guide for details.

7. Optional: email and voice

Both features are off by default and must be configured explicitly.

Shell · email
export REMOTE_PI_MAILDISPATCH_KEY='md_live_...'
pi2web \
  --maildispatch-endpoint https://mail.example.com/api/v1/messages \
  --maildispatch-api-key-env REMOTE_PI_MAILDISPATCH_KEY \
  --maildispatch-notify-to owner@example.com
Shell · voice
export SUMMARY_API_KEY=...
pi2web \
  --voice-base-url http://127.0.0.1:5050/v1 \
  --voice-tts-model edge-tts \
  --voice-tts-voice en-US-AriaNeural \
  --voice-tts-format mp3 \
  --voice-summary-base-url https://llm.example.com/v1 \
  --voice-summary-model <summary-model-id> \
  --voice-summary-api-key-env SUMMARY_API_KEY

8. Reaching the service from other devices

pi2web listens locally by default. To use it from a phone or another computer, prefer the most controlled option available:

  1. SSH port forwarding: ssh -N -L 11318:127.0.0.1:11318 user@dev-host, then open http://127.0.0.1:11318 locally.
  2. Tailscale or another private network: bind to the tailnet address so only your devices can reach it.
  3. devtunnel / Cloudflare Tunnel: no public IP required, but rate limiting is counted per tunnel egress address.
  4. nginx + HTTPS reverse proxy: you handle WebSocket upgrades, TLS certificates, and extra access control yourself.

pi2web does not validate Origin or Host, which makes tunnels easy — and which is exactly why you should never publish the port directly. Browser notifications and the microphone also require a secure context (localhost excepted), another practical reason to use HTTPS. See the secure remote access guide.

9. Upgrade, uninstall, and local development

Shell
# upgrade
npm update -g pi2web

# uninstall (leaves ~/.pi data intact)
npm uninstall -g pi2web

# run from source
git clone https://github.com/sxwxs/pi2web.git
cd pi2web
npm install
npm run check
npm test
npm run dev -- --port 11318

You can inspect the published package locally with npm pack --dry-run or install the tarball with npm install -g ./pi2web-0.2.0.tgz.

10. Troubleshooting

SymptomLikely cause and fix
Native module build fails during installMissing Python 3 or a C/C++ toolchain. Install the platform build tools and retry, or use a Node.js version with prebuilt binaries.
Pairing fails with HTTP 429Failure rate limiting kicked in. Wait for Retry-After, or confirm the code was not rotated.
Pairing code lostIt cannot be recovered. Run pi2web --rotate-access-token.
Agent list empty although history existsThe agent may be archived. Archiving only sets a database flag and never deletes Pi session files.
Notifications or microphone unavailablePlain HTTP over a LAN IP is not a secure context. Use localhost, an SSH tunnel, or HTTPS.
Terminal closes immediatelyCheck that the workspace path exists and that you are below the eight-terminal limit.
Startup fails with MailDispatch errorsEndpoint, API key environment variable, and recipient must all be present, and the endpoint must be an http/https URL.
