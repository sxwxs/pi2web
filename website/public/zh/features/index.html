01
AGENT CONTROL

完整的 Agent 生命周期控制。

pi2web 使用真实的 Pi SDK 启动 Agent，因此浏览器里能做的事情，和你在终端里使用 Pi 时基本一致。

AVAILABLEprompt · steer · follow-up

对话与干预

发送 Prompt、在运行中插入 steer、排队 follow-up，或直接 abort 当前运行。

AVAILABLEnavigate · fork · undo

Session 分支

Tree Navigate 浏览历史节点，从任意节点 Fork 或 Undo，保留 Pi 原生的分支语义。

AVAILABLEmodel · thinking · compact

运行参数

随时切换模型和 Thinking level，必要时对上下文执行 Compact。

AVAILABLEarchive · lazy start

按需启动与归档

重启后 Agent 为 unloaded，读取消息或发送命令时才创建 Pi Session；右键 Archive 只写数据库标记，不动 Session 文件。

事件通道还负责

  • WebSocket sequence 去重
  • 断线指数退避重连
  • 增量 replay 与 snapshot 恢复
  • Extension UI 事件与响应
  • Retry、Tool、Thinking 折叠展示
  • 所有已知 Agent 的完成通知

模型、Provider 认证与配额来自本机 ~/.pi/agent。pi2web 不提供模型能力。

02
SECURITY MODEL

访问控制简单，但边界必须清楚。

只有一层配对码认证：拿到配对码就等于拿到服务进程用户的 Shell。所以限流、存储和暴露方式都需要认真对待。

01

配对码

首次启动仅显示一次，服务端只保存 SHA-256 hash，文件权限 0600。

02

手动输入

Web UI 不从 URL 或服务端自动注入配对码，必须由用户手动输入。

03

可选保存

连接成功后才询问是否写入 localStorage，只有明确确认才保存。

04

失败限流

同一来源 60 秒内失败 10 次即锁定，锁定时间翻倍最长 15 分钟，返回 429 与 Retry-After。

05

轮换

pi2web --rotate-access-token 立即作废旧配对码并输出新的。

06

默认本地

默认监听 127.0.0.1；远程访问建议 SSH 隧道、Tailscale 或 HTTPS 反向代理。

!

Terminal 不是沙箱。 它是以 pi2web 进程用户身份运行的完整宿主机 Shell，可以访问 Workspace 之外的文件和继承的环境变量。请阅读安全远程访问指南。

03
WORKSPACE & TERMINAL

代码就在手边，不用来回切工具。

Workspace 提供目录浏览与文件读取，Terminal 提供真实 Shell，两者与 Agent 显示在同一个列表中。

TREE

目录浏览

按 Workspace 浏览目录树，读取文本文件并分页，二进制文件给出明确提示。

MENTION

@ 引用文件

在输入框输入 @ 浏览并引用 Workspace 内的文件或目录，直接带入 Prompt。

PTY

交互式 Terminal

目录右键即可打开终端，支持输入、resize、输出快照、清屏与关闭。

RECONNECT

刷新重连

刷新浏览器可重新连接仍在运行的终端，最近 512 KiB 输出用于重放。

LIMITS

资源上限

每个服务进程最多同时运行 8 个终端；终端只存在于进程内存，服务退出即结束。

SESSIONS

Session 索引

SQLite 中的轻量索引提供列表、排序与分页，不复制完整消息内容。

04
NOTIFICATIONS

Agent 结束时，用你在意的方式提醒。

浏览器通知、语音播报和邮件通知可以按需组合。语音和邮件默认关闭，需要显式配置才启用。

WEB PUSH

浏览器通知

授权后对所有已知 Agent 提供完成通知；需要 HTTPS 安全上下文（localhost 例外）。

SUMMARY

语音摘要

摘要 LLM 把最终输出压缩成短播报，按句子流式 TTS，多个 Session 排队播放不重叠。

STT

语音输入

配置 --voice-stt-model 后 Web UI 显示麦克风按钮；识别结果只插入输入框，不会自动发送。

MAILDISPATCH

邮件通知

Agent settle 后通过 MailDispatch 提交事务邮件，返回 202 即进入其持久队列。

AGGREGATION

聚合等待

首个任务完成后可等待若干秒，把期间完成的其他任务合并进同一封邮件。

CONTENT

正文可控

可选择是否包含 Agent 最终回复、Session 名称与工作路径；设置保存在服务端数据库。

05
API & CLIENTS

Web UI 之外，还有 API 和 Android 客户端。

除静态资源、/health 和登录接口外，所有请求都需要 Authorization: Bearer <token>，响应统一为 { data } 或 { error }。

REST/api/v1/workspaces · /agents · /sessions

资源管理

创建与查询 Workspace、Agent 与 Session，浏览目录、读取文件与 stat 信息。

REST/api/v1/agents/:id/prompt · steer · abort

Agent 命令

发送指令、切换模型与 Thinking level、命名 Session、Fork、Compact、响应扩展 UI。

WS/api/v1/ws

事件流

支持 sequence、replay、snapshot、fromNow 与 Agent command 下发。

WS/api/v1/terminals/:id/ws

终端通道

输入、窗口 resize、输出快照与退出事件。

Android 客户端

  • Kotlin + Jetpack Compose 原生应用
  • 与 Web UI 共用同一套 API 与配对码
  • Session、Agent 与流式对话
  • 构建说明见仓库 android/README.md
  • 流式 PCM 播放与录音尚未接入

完整能力列表见仓库中的 ANDROID_APP_FEATURES.md。
