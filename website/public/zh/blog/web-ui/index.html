pi2web Web UI 使用说明

配对成功后，浏览器就是完整的 Agent 工作台。这篇说明覆盖 Workspace、Agent、对话控制、文件引用、Terminal，以及断线恢复与通知设置。

1. 连接与配对

打开服务地址（默认 http://127.0.0.1:11318）后，页面要求手动输入配对码。配对码不会从 URL 参数读取，也不会由服务端注入。连接成功后页面会询问是否保存到 localStorage：只有你确认才写入，未确认时配对码仅存在于当前页面的 JS 内存里，刷新即失效。

服务地址、当前 Workspace/Agent 和事件 sequence cursor 会保存在 localStorage，用于刷新后快速恢复视图。

2. Workspace

Workspace 是一个本机目录加一个名称，用于给 Agent 提供初始工作目录并支持文件浏览。

  • 添加 Workspace 后可以浏览目录树，读取文本文件（分页显示），二进制文件会给出明确提示。
  • 在输入框输入 @ 可以浏览并引用 Workspace 内的文件或目录，引用会直接带入 Prompt。
  • 右键目录可以在交互式 Terminal 中打开该路径。
Workspace 不是沙箱。

它只决定初始 cwd。Terminal 与 Agent 都以 pi2web 进程用户身份运行，可以访问 Workspace 之外的文件。

3. 创建与管理 Agent

在 Workspace 下创建 Agent 时可以选择新建 Session 或恢复已有 Session。Agent 与 Terminal 显示在同一个列表中，方便在一个视图里切换。

  • 按需启动：服务重启后 Agent 状态为 unloaded，读取消息或发送命令时才会真正创建 Pi Session；并发请求共享同一次启动。
  • 停止 Agent：只释放运行中的 Session，保留元数据，下次使用会自动重新启动。
  • Archive：右键 Agent 可 Archive，只设置数据库中的 archived_at，不会移动、重命名或删除任何 Pi Session 文件。

4. 对话与干预

输入框支持三类操作，对应 Pi 的原生语义：

操作作用典型场景
Prompt开始一次新的 Agent 运行。提出任务或问题。
Steer在运行过程中插入指示。发现方向偏了，立即纠正。
Follow-up排队等待当前运行结束后执行。先让它跑完，再做下一步。
Abort中止当前运行。需求变了或明显跑偏。

消息流中的 Thinking、Tool 调用、Retry 与 Extension UI 事件都可以折叠展开，长对话不会被工具输出淹没。模型和 Thinking level 可以随时切换，作用于之后的运行。

5. Session 分支与 Compact

Web UI 提供与 Pi 一致的 Session 操作：

  • Session 命名：给会话起名后，列表、通知和语音播报都会使用该名称。
  • Tree Navigate：浏览会话的历史节点。
  • Undo / Fork：回到某个节点重来，或从该节点分叉出新的分支。
  • Compact：压缩上下文，缓解长会话的上下文膨胀。

这些操作作用于 Pi 的 JSONL Session 文件，pi2web 的 SQLite 只维护可重建的索引。

6. Terminal

Terminal 基于 node-pty 与 xterm.js，是完整的宿主机 Shell。

  • 支持输入、窗口 resize、清屏、关闭，以及刷新浏览器后的重连。
  • 每个终端保留最近 512 KiB 输出用于重连重放。
  • 每个服务进程最多同时运行 8 个终端。
  • 终端只保存在服务进程内存中，pi2web 退出或重启时全部结束。

7. 通知与语音

导航栏的“配置”窗口可以启用或关闭邮件通知，并设置聚合等待时间、是否包含 Agent 最终回复、是否包含 Session 名称与工作路径。这些设置保存在服务端数据库中，对所有客户端生效。

浏览器通知需要授权，并且要求 HTTPS 安全上下文（localhost 例外）；授权后对所有已知 Agent 提供完成通知。若服务端配置了语音，页面上会出现“启用语音”按钮，点击后播放服务端推送的 PCM16 或 MP3 音频；配置了 STT 模型时还会显示麦克风按钮，识别结果只插入输入框，不会自动发送。

8. 断线恢复

Web UI 通过 WebSocket 接收事件，并按 sequence 去重。断线后使用指数退避重连，并根据本地保存的 cursor 请求增量 replay 或 snapshot，因此短暂断网、切换 Wi-Fi 或手机休眠都不会丢失中间输出。

浏览器与 Android 的差异。

自定义 Pi TUI Component 无法在浏览器中通用渲染；Android 客户端目前也尚未接入流式 PCM 播放与录音 UI。
