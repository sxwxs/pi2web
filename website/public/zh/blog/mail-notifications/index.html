配置 pi2web 的 Agent 完成邮件通知

离开电脑时，用一封邮件知道 Agent 已经跑完。pi2web 通过 MailDispatch 提交事务邮件，可配置聚合等待时间与正文内容。

1. 什么时候发邮件

Pi 发出 agent_settled 时触发，也就是该 Agent 不会再自动重试、自动 compact 或执行排队的 follow-up。此时任务真的告一段落，适合提醒你回来查看。

pi2web 只负责把邮件提交给 MailDispatch。MailDispatch 返回 202 后邮件进入其持久队列，实际投递由 MailDispatch 的 worker 完成。

2. 启动参数

三个参数必须同时提供，否则 pi2web 会拒绝启动：endpoint、API key 环境变量名和收件人。

Shell
export REMOTE_PI_MAILDISPATCH_KEY='md_live_...'
pi2web \
  --maildispatch-endpoint https://mail.example.com/api/v1/messages \
  --maildispatch-api-key-env REMOTE_PI_MAILDISPATCH_KEY \
  --maildispatch-notify-to owner@example.com \
  --maildispatch-sender-id system
参数是否必需说明
--maildispatch-endpoint必需MailDispatch 消息 API 地址，必须是 http 或 https URL。
--maildispatch-api-key-env必需存放 API key 的环境变量名，而不是 key 本身。
--maildispatch-notify-to必需接收通知的邮箱地址。
--maildispatch-sender-id可选指定 sender；省略时由 MailDispatch 按 API key 与服务配置选择。
API key 只从环境变量读取。

这样密钥不会出现在命令行参数和进程列表中。该 key 至少需要 MailDispatch 的 mail:send scope。

3. 在 Web UI 中调整

导航栏的“配置”窗口可以启用或关闭邮件通知，并设置：

  • 聚合等待时间：首个任务完成后等待指定秒数，期间完成的其他任务合并进同一封邮件；0 表示立即发送。
  • 是否包含 Agent 最终回复。
  • 是否包含 Session 名称和工作路径。

这些设置保存在 pi2web 的 SQLite 元数据数据库中，对所有浏览器客户端和 Agent 生效，服务重启后继续保留。

4. 邮件内容

如果关闭了“包含最终回复”和“包含 Session 信息”，邮件正文只说明一个或多个 Agent 任务已经完成，不含任何项目细节。

注意内容敏感性。

Agent 的最终回复可能包含代码片段、路径或内部信息。邮件会离开你的机器，请按收件邮箱的可信程度决定是否开启这两项。

5. 失败处理

邮件通知失败只写入 pi2web 的标准错误输出，不会改变 Agent 任务状态，也不会阻塞后续运行。排查时可以按这个顺序检查：

  1. 启动日志里是否有参数校验错误（三个必需参数是否齐全、endpoint 是否为合法 URL）。
  2. 环境变量是否在启动 pi2web 的那个 Shell 中真的存在。
  3. API key 是否具备 mail:send scope，以及是否被撤销。
  4. MailDispatch 是否返回 202；若返回其他状态码，错误信息会打印在 pi2web 的 stderr 中。
  5. 邮件已入队但没收到时，检查 MailDispatch 侧的投递日志与收件箱垃圾邮件过滤。
