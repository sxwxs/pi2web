pi2web Android 客户端：构建与连接

仓库中的 android/ 是一个 Kotlin + Jetpack Compose 原生客户端，和 Web UI 共用同一套 API 与配对码。这篇说明覆盖构建、连接与当前能力差异。

2026-07-25pi2web实践指南
本文目录为什么用原生客户端构建连接与配对能力对照使用建议

1. 为什么需要原生客户端

浏览器已经能覆盖大部分场景，但手机上的原生应用在以下方面更顺手：常驻登录状态、系统通知、更好的键盘与滚动体验，以及后台保持连接。Android 客户端连接的仍然是同一个 pi2web 服务，不需要额外部署。

运行时使用真实 SDK。

服务端使用真实的 @earendil-works/pi-coding-agent SDK，并复用 Pi CLI 的 ~/.pi/agent 模型、认证与设置；MockBackend 只用于自动化测试。

2. 构建

目前没有提供预编译 APK，需要自行构建。Android Studio 或命令行均可：

Shell
git clone https://github.com/sxwxs/pi2web.git
cd pi2web/android
./gradlew assembleDebug
# 产物位于 app/build/outputs/apk/debug/

详细的构建要求（JDK、Android SDK 版本等）与连接说明见仓库中的 android/README.md，完整功能列表见 ANDROID_APP_FEATURES.md。

3. 连接与配对

  1. 确认手机可以访问 pi2web 服务地址。默认服务只监听 127.0.0.1，通常需要先建立 SSH 隧道、加入 Tailscale 之类的私有网络，或使用带访问控制的隧道。
  2. 在应用中填写服务地址（例如 http://100.x.y.z:11318）。
  3. 输入配对码。配对码只在服务首次启动或轮换时显示一次；忘记时运行 pi2web --rotate-access-token。

连接方式的取舍与安全建议见安全远程访问指南。

5. 使用建议

  • 手机端更适合“跟进与干预”，复杂的重构任务仍然建议在电脑上发起。
  • 移动网络切换频繁，客户端依赖 WebSocket 的 sequence 去重与增量 replay 恢复，短暂断线不会丢消息。
  • 配对码等同 Shell 权限，请只在自己的设备上保存，并给手机本身设置锁屏。
  • 不再使用某台设备时，直接轮换配对码即可让它失效。
