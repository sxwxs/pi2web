pi2web 安装与配置指南

pi2web 通过一个 npm 包提供服务端、Web UI 和 API。这篇指南从环境要求讲到命令行选项、配对码管理、数据目录、可选的邮件与语音功能，以及常见故障排查。

1. 环境要求

pi2web 是 Pi Coding Agent 的远程外壳：它在你的开发机上启动真实的 @earendil-works/pi-coding-agent SDK，并把能力通过 HTTP/WebSocket 暴露给浏览器和 Android 客户端。因此，运行前需要先确认三件事。

  • Node.js 20.10 或更高版本，用 node -v 检查。
  • 可用的 Pi 配置：模型、Provider 认证和设置全部复用本机 ~/.pi/agent。如果你还没在这台机器上用过 Pi，请先完成 Pi 自身的模型配置。
  • 原生模块构建条件：安装会准备 better-sqlite3 与 node-pty。多数平台直接使用预编译产物；没有预编译产物的平台需要 Python 3 与 C/C++ 工具链（Linux 的 build-essential、macOS 的 Xcode Command Line Tools、Windows 的 Visual Studio Build Tools）。
pi2web 不提供模型或额度。

它不代理模型请求，也不托管代码。所有推理都由你本机 Pi 配置中的 Provider 完成。

2. 安装

npm 包名和全局命令都是 pi2web。

Shell
npm install -g pi2web
pi2web --version

如果不想全局安装，也可以用 npx pi2web 临时运行；但长期使用建议全局安装，避免每次重新下载原生模块。

3. 首次启动与配对码

直接运行 pi2web 即可。服务默认监听 127.0.0.1:11318，同时提供 API、WebSocket 和 Web UI，不需要另起静态文件服务器。

Shell
pi2web --host 127.0.0.1 --port 11318

首次启动会在终端显示一次配对码，这是唯一一次明文输出。服务端只保存它的 SHA-256 hash（在数据目录的 auth.json 中，文件权限 0600），所以忘记后无法找回，只能轮换：

Shell
pi2web --rotate-access-token

该命令生成新的配对码并立即作废旧配对码，然后退出。打开浏览器访问终端显示的地址后，必须手动输入配对码：Web UI 不会从 URL 或服务端自动注入。连接成功后页面才会询问是否保存到 localStorage，只有你明确确认才写入，请只在可信设备上确认。

配对失败有限流。

同一来源地址在 60 秒窗口内累计 10 次失败后被锁定，锁定时间从 60 秒起按次翻倍，最长 15 分钟，HTTP 返回 429 与 Retry-After，WebSocket 升级同样受限；一次成功配对立即清除计数。注意限流按 TCP 来源地址统计，通过隧道或反向代理访问时所有客户端共用同一个计数桶。

4. 命令行选项

pi2web --help 会列出全部选项。常用部分如下。

选项默认值说明
--host <address>127.0.0.1监听地址。改成 0.0.0.0 前请先阅读远程访问部分。
--port <number>11318监听端口。
--data-dir <path>~/.pi/remote-pi元数据目录，也可用环境变量 PI_REMOTE_DIR 指定。
--rotate-access-token—生成新配对码并退出，旧配对码立即失效。
--maildispatch-endpoint <url>关闭MailDispatch 消息 API endpoint。
--maildispatch-api-key-env <name>关闭存放 MailDispatch API key 的环境变量名。
--maildispatch-notify-to <email>关闭接收 Agent 完成通知的邮箱。
--maildispatch-sender-id <id>可选指定 MailDispatch sender；省略时由服务端按 API key 选择。
--voice-base-url <url>关闭OpenAI 兼容语音服务地址；不配置则语音功能完全关闭。
--voice-tts-model / --voice-tts-voice—启用语音时必填的 TTS 模型与音色。
--voice-stt-model <id>可选配置后 Web UI 才显示麦克风按钮。
--voice-summary-base-url / --voice-summary-model—生成播报摘要的 LLM endpoint 与模型。
--voice-request-timeout <ms>120000语音与摘要请求超时，超时后降级为文本提示。
--version / --help—打印版本或帮助。

MailDispatch 的三个选项必须同时提供，否则 pi2web 会拒绝启动。语音相关选项只有在配置了 --voice-base-url 时才会被校验。所有 API key 都通过环境变量名传入，避免密钥出现在命令行参数和进程列表中。

5. 数据与持久化

服务端元数据保存在 ~/.pi/remote-pi/remote-pi.db 这个 SQLite 数据库中（WAL 模式）：

  • workspaces：Workspace ID、名称、根目录和创建时间。
  • agents：Agent 与 Workspace/Session 的映射、cwd、状态、创建与最后活动时间以及 Archive 状态。
  • sessions：用于列表、排序和分页的轻量索引，包括名称、文件路径、消息数量与 mtime/size。
  • auth.json：配对码的 SHA-256 hash 及创建、轮换时间，单独保存，不含明文。

完整对话仍由 Pi 的 SessionManager 以 JSONL 管理，默认位于 ~/.pi/agent/sessions/<编码后的-cwd>/。SQLite 只保存可重建的索引，不复制消息内容。Terminal 只存在于服务进程内存中，进程退出即全部结束。

Shell
# 想把元数据放到别处，例如加密卷
pi2web --data-dir ~/pi2web-data

注意更换数据目录相当于换了一套配对码与 Agent 元数据，Pi 自身的 Session 文件不受影响。

6. 添加 Workspace 与创建 Agent

配对成功后，第一件事是添加 Workspace：填写一个本机目录（通常是代码仓库根目录）和一个名称。之后你可以：

  • 在该 Workspace 下创建 Agent，Agent 的 cwd 即 Workspace 路径；
  • 浏览目录树、分页读取文本文件；
  • 右键目录，在交互式 Terminal 中打开；
  • 在输入框用 @ 引用文件或目录。

Agent 元数据保存在 SQLite 中，服务重启后状态为 unloaded，不会立即创建 Pi AgentSession。只有读取消息、Session、能力或发送命令时才按需启动，并发请求共享同一次启动。“停止 Agent”只释放运行中的 Session，元数据仍然保留。详见 Web UI 使用说明。

7. 可选功能：邮件与语音

两项功能默认关闭，都需要显式配置。

Shell · 邮件通知
export REMOTE_PI_MAILDISPATCH_KEY='md_live_...'
pi2web \
  --maildispatch-endpoint https://mail.example.com/api/v1/messages \
  --maildispatch-api-key-env REMOTE_PI_MAILDISPATCH_KEY \
  --maildispatch-notify-to owner@example.com
Shell · 语音播报
export SUMMARY_API_KEY=...
pi2web \
  --voice-base-url http://127.0.0.1:5050/v1 \
  --voice-tts-model edge-tts \
  --voice-tts-voice zh-CN-XiaoxiaoNeural \
  --voice-tts-format mp3 \
  --voice-summary-base-url https://llm.example.com/v1 \
  --voice-summary-model <summary-model-id> \
  --voice-summary-api-key-env SUMMARY_API_KEY
邮件通知完整配置 →聚合等待时间、正文开关与失败处理 语音摘要与语音输入 →Speaches 与 Edge TTS 两种方案

8. 从其他设备访问

pi2web 默认只监听本机。要在手机或另一台电脑上使用，推荐按可控程度从高到低选择：

  1. SSH 端口转发：ssh -N -L 11318:127.0.0.1:11318 user@dev-host，然后在本地浏览器访问 http://127.0.0.1:11318。
  2. Tailscale 等私有网络：把服务绑定到 tailnet 地址，只在设备网络内可达。
  3. devtunnel / Cloudflare Tunnel：无需公网 IP，但注意限流会按隧道出口地址统计。
  4. nginx + HTTPS 反向代理：需要自行处理 WebSocket 升级、TLS 证书和额外访问控制。

pi2web 不校验 Origin / Host，因此可以直接配合内网穿透使用；但也正因如此，不要把端口直接暴露到公网。浏览器通知与麦克风都要求 HTTPS 安全上下文（localhost 例外），这也是使用 HTTPS 隧道的一个实际理由。完整方案见安全远程访问指南。

9. 升级、卸载与本地开发

Shell
# 升级
npm update -g pi2web

# 卸载（不会删除 ~/.pi 数据）
npm uninstall -g pi2web

# 从源码运行
git clone https://github.com/sxwxs/pi2web.git
cd pi2web
npm install
npm run check
npm test
npm run dev -- --port 11318

发布包也可以本地检查：npm pack --dry-run，或安装打包产物 npm install -g ./pi2web-0.2.0.tgz。

10. 故障排查

现象可能原因与处理
安装时原生模块编译失败缺少 Python 3 或 C/C++ 工具链。安装对应平台的构建工具后重试，或改用有预编译产物的 Node.js 版本。
页面提示配对失败并返回 429触发失败限流。等待 Retry-After 指示的时间，或确认配对码是否已被轮换。
忘记配对码无法找回，运行 pi2web --rotate-access-token 生成新的。
Agent 列表为空但历史存在Agent 可能被 Archive；Archive 只写数据库标记，不会删除 Pi 的 Session 文件。
浏览器无法启用通知或麦克风通过局域网 IP 的 HTTP 地址访问时不是安全上下文。改用 localhost、SSH 隧道或 HTTPS。
Terminal 打开后立即结束检查 Workspace 路径是否存在，以及是否已达到 8 个终端的上限。
启动时报 MailDispatch 参数错误endpoint、API key 环境变量和收件人必须三者同时提供，且 endpoint 必须是 http/https URL。
