配置 pi2web 的语音摘要与语音输入

pi2web 可以在 Agent 结束后朗读一段摘要，也可以用麦克风口述 Prompt。这需要两个 OpenAI 兼容服务：一个摘要 LLM，一个语音服务。本文给出 Speaches 与 Edge TTS 两种配置。

本文目录工作方式方案一：Edge TTS方案二：Speaches参数说明在 Web UI 中使用限制与排查

1. 工作方式

语音默认关闭，只有配置 --voice-base-url 才会启用。启用后的流程是：

  1. Pi 发出 agent_settled（不会再自动重试、自动 compact 或执行排队的 follow-up）。
  2. pi2web 取最后一条 Assistant 文本，移除代码块、长链接和 Markdown，并限制摘要输入长度。
  3. 摘要 LLM 以流式 Chat Completions 生成短播报；只要出现完整句子就立即调用流式 TTS，不必等整段摘要完成。
  4. 音频通过已认证的 Agent WebSocket 推送到浏览器播放。

多个 Session 接近同时完成时，播报进入全局队列依次播放，不会重叠；有 Session 名称时以“会话{name}已完成：”开头。新的 Agent 运行会取消该 Agent 尚未完成的播报。

语音流不写入历史。

音频只实时投递，不写入 Session，也不参与事件 replay。

2. 方案一：Edge TTS（只要朗读）

如果只需要“说出来”，不需要语音识别，仓库内的 packages/edge-tts-server 是最轻的选择：基于 Python edge-tts 和 aiohttp，直接返回 MP3，不需要 Docker 或 FFmpeg。

Shell
cd packages/edge-tts-server
python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -e .
remote-pi-edge-tts
Shell
export SUMMARY_API_KEY=...
pi2web \
  --voice-base-url http://127.0.0.1:5050/v1 \
  --voice-tts-model edge-tts \
  --voice-tts-voice zh-CN-XiaoxiaoNeural \
  --voice-tts-format mp3 \
  --voice-summary-base-url https://llm.example.com/v1 \
  --voice-summary-model <summary-model-id> \
  --voice-summary-api-key-env SUMMARY_API_KEY

该模式没有配置 --voice-stt-model，因此只启用播报，不启用语音识别。Edge TTS 使用非官方消费者服务，适合本地和实验性使用。

3. 方案二：Speaches（朗读 + 识别）

需要语音输入时，使用一个同时提供 TTS 与 STT 的 OpenAI 兼容服务，例如 Speaches。Windows 下的启动、模型下载与故障排查见仓库中的 VOICE_SERVER_SETUP.md。

Shell
# 示例模型 ID 需要替换为服务中实际下载的模型
export SUMMARY_API_KEY=...
pi2web \
  --voice-base-url http://127.0.0.1:8000/v1 \
  --voice-stt-model <stt-model-id> \
  --voice-tts-model <tts-model-id> \
  --voice-tts-voice <voice-id> \
  --voice-summary-base-url https://llm.example.com/v1 \
  --voice-summary-model <summary-model-id> \
  --voice-summary-api-key-env SUMMARY_API_KEY \
  --voice-language zh-CN

4. 参数说明

参数说明
--voice-base-urlOpenAI 兼容语音服务地址。不配置则语音功能完全关闭。
--voice-tts-model / --voice-tts-voice启用语音时必填的 TTS 模型 ID 与音色 ID。
--voice-tts-formatpcm（默认）或 mp3，取决于语音服务实际支持的输出。
--voice-stt-model可选。配置后 Web UI 才显示麦克风按钮。
--voice-api-key-env存放语音服务 API key 的环境变量名。
--voice-summary-base-url / --voice-summary-model生成播报摘要的 LLM endpoint 与模型。
--voice-summary-api-key-env存放摘要 LLM API key 的环境变量名。
--voice-language播报语言标签，默认 zh-CN。
--voice-request-timeout摘要、合成与识别的单次请求超时，默认 120000 毫秒，最小 1000。

API key 一律通过环境变量名传入，不直接写在命令行参数中，避免出现在进程列表里。

5. 在 Web UI 中使用

  • 点击“启用语音”后开始播放服务端推送的 PCM16 或 MP3 音频。浏览器通常要求用户交互后才允许自动播放，这也是需要点一下的原因。
  • 配置了 STT 模型时会显示麦克风按钮；识别文字只插入输入框，不会自动发送，你仍然可以先修改再提交。
  • 麦克风要求 HTTPS 安全上下文（localhost 例外）；通过局域网 IP 的 HTTP 地址访问时无法使用。

6. 限制与排查

现象处理
没有任何播报确认启动参数中有 --voice-base-url，且页面已点击“启用语音”。
播报变成文本提示摘要或 TTS 请求超时。提高 --voice-request-timeout，或检查语音服务负载。
没有麦克风按钮未配置 --voice-stt-model，或访问地址不是安全上下文。
音频断续或格式错误尝试切换 --voice-tts-format（pcm ↔ mp3），确认服务端实际支持的格式。
Android 上没有语音Android 客户端的流式 PCM 播放与录音 UI 尚未接入。
