Your Pi Coding Agent,

pi2web runs Pi Coding Agent on your own development machine and exposes it through a pairing-code protected HTTP/WebSocket service with a web UI and a native Android client. Sessions, models, and code stay local — you just gain another screen.

WHY PI2WEB

Long-running agents belong
on the machine with your code.

The repository, the toolchain, and the credentials are already there. The only thing missing is a remote surface you can take over from at any time.

01

Take over anywhere

The browser and the Android client talk to the same service. Follow streaming output, add instructions, steer, or abort after you walk away from the desk.

02

Local by default

Binds to 127.0.0.1, requires a manually typed pairing code, stores only its SHA-256 hash, and rate-limits failed attempts with exponential lockout.

03

Survives bad networks

WebSocket sequence de-duplication, exponential backoff, and incremental replay/snapshot recovery. Agent metadata lives in SQLite and reloads on demand.

HOW IT WORKS

One process between every client and your local Pi.

pi2web starts agents through the real @earendil-works/pi-coding-agent SDK and reuses the Pi CLI directory for models, authentication, and settings.

MORE THAN A VIEWER

Everything remote control actually needs.

Terminals, files, notifications, voice, email, and persistence come from a single process. Nothing else to deploy.

AGENTS

Parallel workspaces and agents

Create a workspace per repository and manage agents and terminals in one list. Agent metadata is stored in SQLite; after a restart agents are unloaded and a Pi session is only created when you actually use them.

TERMINAL

Interactive terminals

Real shells backed by node-pty with input, resize, output snapshots, and reconnect after a refresh. Up to eight per server process.

service-api runningweb-client 12mbash · ~/code 1h
VOICE

Spoken summaries and dictation

A summary LLM condenses the final answer and streams it to TTS. Add an STT model and you can dictate prompts too.

Voice featuresOFF BY DEFAULT
MAIL

Completion emails

Send transactional mail through MailDispatch when a task settles, with a configurable aggregation window and body options.

PERSISTENCE

Durable metadata

SQLite in WAL mode stores workspaces, agents, and a session index. Full conversations stay in Pi's JSONL session files.

SECURITY FIRST

Treat the service like a shell key.

Terminals are full host shells running as the pi2web process user, and a workspace path only sets the initial working directory — it is not a sandbox. Reach the service through an SSH tunnel, Tailscale, or an HTTPS reverse proxy with access control instead of publishing the port.

QUICKSTART

Three steps to a running service.

Read the full setup guide
STEP 01

Install globally

Node.js 20.10+ required. Installation prepares the better-sqlite3 and node-pty native modules.

npm install -g pi2web
STEP 02

Start the server

The pairing code is printed once on first startup. Save it immediately.

pi2web --host 127.0.0.1 --port 11318
STEP 03

Open and pair

Visit http://127.0.0.1:11318, type the pairing code, and add your first workspace.

pi2web --rotate-access-token
