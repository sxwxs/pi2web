Configure voice summaries and speech input in pi2web

pi2web can read out a short summary when an agent finishes, and can transcribe dictated prompts. Both need two OpenAI-compatible services: a summary LLM and a speech endpoint. Here are the Speaches and Edge TTS setups.

1. How it works

Voice is disabled unless --voice-base-url is set. Once enabled the flow is:

  1. Pi emits agent_settled: no more automatic retries, automatic compaction, or queued follow-ups.
  2. pi2web takes the last assistant message, strips code blocks, long links, and Markdown, and caps the summary input length.
  3. The summary LLM streams chat completions; as soon as a full sentence appears, streaming TTS starts, so playback does not wait for the whole summary.
  4. Audio is pushed to the browser over the authenticated agent WebSocket.

When several sessions settle at nearly the same time, announcements enter a global queue and play one after another instead of overlapping. Named sessions are announced with the session name first. A new run cancels any pending announcement for that agent.

Audio is never persisted.

Voice streams are delivered live only; they are not written to sessions and do not take part in event replay.

2. Option one: Edge TTS (playback only)

If you only want spoken summaries, the packages/edge-tts-server service in the repository is the lightest path: Python edge-tts plus aiohttp, returning MP3 directly with no Docker and no FFmpeg.

Shell
cd packages/edge-tts-server
python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -e .
remote-pi-edge-tts
Shell
export SUMMARY_API_KEY=...
pi2web \
  --voice-base-url http://127.0.0.1:5050/v1 \
  --voice-tts-model edge-tts \
  --voice-tts-voice en-US-AriaNeural \
  --voice-tts-format mp3 \
  --voice-summary-base-url https://llm.example.com/v1 \
  --voice-summary-model <summary-model-id> \
  --voice-summary-api-key-env SUMMARY_API_KEY \
  --voice-language en-US

Because --voice-stt-model is absent, this mode enables announcements only. Edge TTS relies on an unofficial consumer service and suits local, experimental use.

3. Option two: Speaches (playback and dictation)

For speech input, run one OpenAI-compatible service that provides both TTS and STT, such as Speaches. Windows setup, model downloads, and troubleshooting are documented in VOICE_SERVER_SETUP.md in the repository.

Shell
# Replace the example IDs with models actually downloaded in your service
export SUMMARY_API_KEY=...
pi2web \
  --voice-base-url http://127.0.0.1:8000/v1 \
  --voice-stt-model <stt-model-id> \
  --voice-tts-model <tts-model-id> \
  --voice-tts-voice <voice-id> \
  --voice-summary-base-url https://llm.example.com/v1 \
  --voice-summary-model <summary-model-id> \
  --voice-summary-api-key-env SUMMARY_API_KEY \
  --voice-language en-US

4. Flag reference

FlagDescription
--voice-base-urlOpenAI-compatible speech endpoint. Without it, voice stays off entirely.
--voice-tts-model / --voice-tts-voiceRequired TTS model and voice IDs when voice is enabled.
--voice-tts-formatpcm (default) or mp3, depending on what your service returns.
--voice-stt-modelOptional. Enables the microphone button in the web UI.
--voice-api-key-envName of the environment variable holding the speech API key.
--voice-summary-base-url / --voice-summary-modelEndpoint and model used to write the spoken summary.
--voice-summary-api-key-envName of the environment variable holding the summary API key.
--voice-languageSpoken summary language tag; defaults to zh-CN.
--voice-request-timeoutPer-request timeout for summary, synthesis, and transcription. Defaults to 120000 ms, minimum 1000.

API keys are always passed as environment variable names so they never appear in command lines or process listings.

5. Using it in the web UI

  • Click "enable voice" to start playing PCM16 or MP3 audio pushed by the server. Browsers generally require a user gesture before audio can autoplay, which is why the button exists.
  • With an STT model configured a microphone button appears; the transcript is inserted into the composer and never sent automatically, so you can edit it first.
  • Microphone access requires a secure context (localhost excepted), so plain HTTP over a LAN IP will not work.

6. Limits and troubleshooting

SymptomFix
No announcements at allConfirm --voice-base-url is set and that you clicked "enable voice" in the page.
Announcement degrades to a text noticeThe summary or TTS request timed out. Raise --voice-request-timeout or check the speech service load.
No microphone button--voice-stt-model is not configured, or the page is not in a secure context.
Choppy or invalid audioSwitch --voice-tts-format between pcm and mp3 to match what the service actually returns.
No voice on AndroidStreaming PCM playback and the recording UI are not wired into the Android client yet.
